# Starfeed

把值得看的 GitHub 项目变成可以浏览、搜索和收藏的信息流。

手机上是双列发现流和底部导航；电脑上自动切换为顶部导航、顶部搜索和四列内容区。两端使用同一个网址、同一个 GitHub 账号和同一份 Stars。

## 直接使用

- 网页：<https://echo-builds-starfeed.vercel.app/>
- 手机：用 Safari 或 Chrome 打开同一链接，也可以安装到主屏幕，像普通 App 一样启动。

## 网页、手机和 PWA

- 小屏幕使用双列卡片、底部搜索和底部导航；发现页持续下滑会自动加载更早的项目。
- 平板自动切换为三列；桌面切换为四列、顶部导航和顶部搜索。
- `manifest.webmanifest`、应用图标和 Service Worker 让网站可以安装到手机或电脑，并在断网时打开最近缓存的页面。
- 项目详情会生成带 `repo` 参数的独立网址，复制地址即可把具体项目分享给别人。
- 收藏由 GitHub Stars 承载，换设备登录同一 GitHub 账号即可恢复。

## 本地预览

只预览推荐与搜索页面时，可在源码目录运行：

```sh
python3 -m http.server 4173
```

打开 <http://localhost:4173>。GitHub 登录和 Stars 同步依赖 Vercel Functions，本地静态服务器不会运行 `/api`。

## GitHub 登录与收藏同步

- 用户通过 GitHub App 登录，应用只申请 Stars 读取和写入权限。
- GitHub Token 不写入前端，也不保存在 `localStorage`；后端将访问令牌和刷新令牌加密后放入 `HttpOnly`、`Secure`、`SameSite=Lax` Cookie。
- 登录后导入最多 1000 个历史 Stars，按仓库 Topics、名称和简介归入中文主题，并用于调整推荐顺序。
- 登录前的本机收藏不会自动批量写入 GitHub；页面会让用户选择是否导入。
- 在 Starfeed 收藏或取消收藏会同步调用 GitHub Stars API。换设备后登录同一 GitHub 账号即可恢复收藏与兴趣画像。

Vercel 需要配置以下环境变量：

```text
GITHUB_CLIENT_ID
GITHUB_CLIENT_SECRET
SESSION_SECRET
```

`SESSION_SECRET` 至少 32 个随机字符。GitHub App 的回调地址设置为：

```text
https://<Vercel 域名>/api/auth/callback
```

## 推荐、更新和日期

- 发现页直接查询 GitHub Search API，只展示至少 500 Star、非归档、非 Fork 的公开仓库。
- 每次进入都会重新获取最近时间段的数据，不设置手动刷新按钮；持续下滑时，以 14 天为一个时间窗口继续加载更早的项目。
- 整体顺序按仓库创建时间从新到旧，同一时间再参考 Star。这样时间方向稳定，不会因为一个老项目刚有提交就反复回到顶部。
- GitHub Search 单次查询最多返回 1000 条结果，因此页面用连续时间窗口拆分查询，而不是依赖单个无限分页。
- 发现流统一显示仓库创建日期，用它保证从上到下时间越来越早；人工整理的详情页可以补充 GitHub 最新正式版本的发布时间。取不到日期时显示「日期暂缺」，不估算发布日期。
- 首页可显示真实产品画面，也可使用统一文字封面。详情页不增加说明条或编辑自拟栏目：项目提供官方中文 README 时，按 README 原有标题、段落和列表原文展示；仅有英文 README 时，逐段翻译并保留原有结构。
- README 详情未完成获取和核对的项目不进入推荐流，不向用户展示占位详情页。
- 详情页底部只保留三个操作：查看 GitHub、在线体验或客户端下载安装、收藏。人工整理过的项目使用站内中文详情；长尾高星项目直接打开原 GitHub 仓库。无法连接时继续使用最近缓存或预载数据。登录前收藏保存在当前浏览器；登录后与 GitHub Stars 双向同步。

## 自然语言搜索

- 首页底部搜索框支持直接描述需求，例如「找能把播客翻译成中文的项目」。页面会把常见中文需求转换为 GitHub 项目作者常用的英文关键词，再调用 GitHub Search API 实时查找。
- 搜索结果至少 500 Star，排除归档仓库和 Fork，默认按 Star 从高到低排列。已完成中文详情核对的项目打开站内详情；其他实时搜索结果直接打开原 GitHub 仓库，避免展示未经准备的占位详情。
- 当前版本使用本地意图词典，不依赖模型服务。它能覆盖常见产品、AI、音视频、翻译和效率工具需求；要支持像 GPT 一样理解任意复杂描述，需要在部署时增加服务端模型和缓存层。
